Subject: [SRU][N][PATCH 0/1] Fix provided-buffer-ring reserved-field validation

BugLink: https://bugs.launchpad.net/bugs/2162843

[Impact]
Valid buffer-ring registration, unregistration and status requests fail
with EINVAL. Requests with nonzero reserved bytes pass the checks.
Several Twelve Dollar Server Challenge entries already retry registration
with reserved bits set to get around this.

[Fix]
Remove the negation from three memchr_inv() checks in io_uring/kbuf.c.
The upstream mem_is_zero() change is correct. Ubuntu's adaptation kept
the negation even though the two helpers have opposite results.

[Test Plan]
Run pbuf_reserved.c with 6.8 UAPI headers. All 17 checks should pass.
The official 6.8.0-139-generic kernel fails all 17 in QEMU.
I also built two kernels from Ubuntu 6.8.0-139.139 with the same minimal
x86-64 config and initramfs: 17 failures before the fix, 17 passes after it.
I haven't tested the full generic build. The unmodified minimal build
warns about unused err in init/do_mounts.c; kbuf.c has no new warning.

[Where problems could occur]
Code using nonzero reserved fields as a workaround needs to send valid
zero-filled requests. Allocation and ring lifetime handling are unchanged.

[Other Info]
The patch applies to Noble 136, 139, 147 and 149 sources. Noble master-next
6dcf89bf9d1650d117680189bf4bbb596af7ab84 still has the bug.

Bluefield tag Ubuntu-bluefield-6.8.0-1035.40, at release commit
f5285baaf0cbec83f2841e900a4f7cfaf5adf485, already contains this correction.
Its kbuf.c matches the affected Noble file with these three changes.
The Bluefield log lists the existing fix as
1473fb4e7a3198b834878dce273d2311738a353a by Uri Dar.
